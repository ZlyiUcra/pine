# 001 - План реалізації

Супроводжує [spec.md](spec.md). Кожне рішення тут або прийнято консиліумом, або виміряно.

## Транспорт: чотири плоти

Каналу браузер → Pine не існує. Канал Pine → браузер один: **статус-лінія, і це DOM**.
Прецедент робочий - `tv-green-diamond.user.js` читає звідти сентінели MAR1.

### Виміряно, не припущено

Пробний плот 2026-07-27 на M1 JPY-парі:

```
plot(1234512345, 'PROBE10')  ->  1,234,512,345.000
plot(123451,     'PROBE6')   ->  123,451.000
```

Десять цифр доходять цілими і в порядку. Експоненційного запису немає. Отже:

- пакування **по десять слотів на число**, три числа - не пʼять;
- читач **зрізає роздільники розрядів**;
- читач **ріже по десятковій крапці** - кількість знаків успадковується від символу
  графіка і на пʼятизначній парі буде інша.

### Алфавіт станів зсунутий на одиницю

| Цифра | Стан |
|---|---|
| `1` | слот не в скані - знято галочку або порожній символ |
| `2` | idle |
| `3` | armed |
| `4` | running |
| `5` | no data - символ не резолвиться |

**Нуль не використовується взагалі**, і це блокуюче зауваження `nitpicker` з вердикту.
Стан `0` у першому слоті перетворив би `0000102000` на `102000`: провідні нулі зникають
безслідно і зсувається **весь** розбір, а не губиться один слот. Із алфавітом від одиниці
число завжди рівно десятизначне і самоописове.

Максимум `5555555555` ≈ 5.6e9 при точному цілому діапазоні double 2^53 ≈ 9e15.

### Розкладка

| Плот | Слоти |
|---|---|
| `STATE1` | 1-10, слот 1 - старша цифра |
| `STATE2` | 11-20 |
| `STATE3` | 21-30 |
| `LISTSUM` | контрольна сума списку пар |

## Контрольна сума

Звірка за довжиною списку **не працює** - друге блокуюче зауваження. `scanned` рахує
активні слоти, а список у розширенні всі тридцять; знята галочка ламала б звірку, нічого
не порушивши. І довжина не ловить перестановку.

Замість неї - сума, чутлива і до складу, і до порядку:

```
LISTSUM = ( Σ по живих слотах i: i × Σ по символах тікера: pos(ALPHABET, символ) ) mod 99991
```

- `ALPHABET` = `ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789` - однаковий рядок з обох боків.
- Тікер береться після `shortName()`, тобто без префікса біржі: `EURUSD`, не `FX:EURUSD`.
- `99991` - просте число під 100000, отже сума завжди вміщується в пʼять цифр.
- Pine не має функції коду символу; позиція береться через `str.pos(ALPHABET, ch)` по
  одному символу з `str.substring`. Рахується один раз і тримається у `var`.

Розширення рахує те саме зі свого списку. Не збіглося - критерій приймання 4.

## Читач

Нового коду нормалізації **не пишемо**. `readFlagText()` у `tv-green-diamond.user.js`
уже робить рівно те, що виміряний рендер вимагає:

```js
.replace(/[−‒–—―]/g, '-')     // Unicode-мінус у деяких локалях
.replace(/[\s,  ]/g, '');     // роздільники: коми, пробіли, нерозривні
```

Береться як є. Далі - різати по `.`, читати цифри зліва направо.

Легенду шукати **за назвою індикатора**, не за позицією рядка: на графіку тепер і `MAR1`,
і `MAR1 Scanner`.

## Стани відмови

Кожен зі своїм текстом - критерій приймання 5.

| Стан | Причина |
|---|---|
| сканера не видно | індикатор не доданий на графік або перейменований |
| значення не читаються | статус-лінія вимкнена в налаштуваннях графіка |
| розбір не вдався | формат змінився - число не десятизначне |
| списки розійшлися | `LISTSUM` не збігається; пари не показуються |

## Чого свідомо не робимо

Не чіпаємо `indicator()`. Спокуса поставити `precision = 0` і позбутися десяткових є, але
це змінює відображення **всіх** значень скрипта заради економії одного `split('.')` у
читачі. Ціна не варта.
